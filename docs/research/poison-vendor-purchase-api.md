# WoW Forever vendor and purchase API notes

Research date: 2026-11-14. Target: the WoW Forever client this repository names in its README. **Do not use the 1.12-era API model for this client.** The authoritative Forever UI source is Blizzard's extracted `forever` branch in Gethe's mirror; the merchant UI is under `Blizzard_UIPanels_Game/Mainline`, and generated API docs use modern `C_*` namespaces.

## Supported read APIs

- **Merchant inventory:** `C_MerchantFrame.GetItemInfo(index)` returns a `MerchantItemInfo` table with `name`, `texture`, `price`, `stackCount`, `numAvailable`, `isPurchasable`, `isUsable`, `hasExtendedCost`, and related fields. It may return nothing. Blizzard's Forever merchant frame gets the complete listing length via the legacy `GetMerchantNumItems()` and retrieves item IDs with `GetMerchantItemID(index)`, then iterates indices `1..numMerchantItems`; the generated MerchantFrame docs do not declare `GetMerchantNumItems`, so its compatibility status is established here only by Blizzard UI source. Source: [MerchantFrame API docs](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/MerchantFrameDocumentation.lua), [Blizzard Forever MerchantFrame.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/MerchantFrame.lua).
- **Inventory counts:** `C_Item.GetItemCount(itemInfo, includeBank, includeUses, includeReagentBank, includeAccountBank)` returns a count. All optional flags default false; for a carried-material planner, call with bank/reagent/account-bank excluded. `C_Container.GetContainerItemInfo(containerID, slotIndex)` returns container slot info (and may return nothing), if direct bag scanning is needed. Sources: [Item API docs](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/ItemDocumentation.lua), [Container API docs](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/ContainerDocumentation.lua).
- **Free space:** `C_Container.CalculateTotalNumberOfFreeBagSlots()` returns total free bag slots. Per bag, `C_Container.GetContainerNumFreeSlots(bagIndex)` returns `numFreeSlots` and optional `bagFamily`. Source: [Container API docs](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/ContainerDocumentation.lua).
- **Money:** Forever's Blizzard `MerchantFrame.lua` itself calls `GetMoney()` when calculating how many stacks a user can afford. The global is therefore used by the shipped merchant UI, but I did not find a generated Forever API declaration in the reviewed source. Treat the signature as known from Blizzard use (current copper total), but direct addon availability/taint behavior is **not independently proven** by generated docs. Source: [Blizzard Forever MerchantFrame.lua](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/MerchantFrame.lua).

## Purchases and user action boundary

Blizzard's Forever merchant UI calls the legacy global `BuyMerchantItem(index[, quantity])` from its item-button click/split-stack paths. The generated `MerchantFrameDocumentation.lua` does **not** declare `BuyMerchantItem`; the source demonstrates Blizzard's own UI use, not that arbitrary addon Lua can call it successfully or without protection. I found no primary-source declaration establishing addon-call policy, repeat-call limits, max quantity, or a safe addon-triggered purchase route. Keep those behaviors **unknown** pending in-client verification. The source shows multi-stack selection as a user-modified click that opens `StackSplitFrame`; this establishes a deliberate UI path, not a license to loop purchases.

The requested product behavior is a configurable reagent popup with an explicit Buy button and a separate optional auto-buy setting (off by default). Research cannot establish whether arbitrary addon code may call `BuyMerchantItem`, whether such calls are protected, or how rapid calls are handled. The implementation therefore wraps calls, requests only the currently previewed amounts, caps them against stock/funds/bag capacity, blocks purchases at Blizzard's high-value confirmation threshold, and reports observed bag changes. Auto-buy runs once per merchant session only when explicitly enabled. Treat both purchase paths as experimental until verified in the current Forever client; if the client blocks them, keep Blizzard's own merchant controls as the fallback. Never simulate UI clicks, bypass protected actions, or report a purchase as completed based only on a function return.
